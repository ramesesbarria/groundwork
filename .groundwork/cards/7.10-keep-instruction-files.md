## Goal
Running `init` on an existing project can't lose its `CLAUDE.md` or `AGENTS.md`. Planned changes: PLAN.md §7.10.

## Acceptance criteria
- [x] A test: an existing CLAUDE.md and AGENTS.md keep every original line after `init`, plus the pointer lines
- [x] No overwrite prompt for these two files
- [x] A fresh folder still gets the full templates
- [x] `doctor`'s CLAUDE.md check still passes

## How to check
In an empty folder, write a CLAUDE.md with a couple of your own rules, then run `npx groundwork-ai init --adapter claude-code`. It doesn't ask about CLAUDE.md, your rules are still there, and `@AGENTS.md` is added at the end.

## Evidence
- Tests before: 4 of 6 new tests fail; the 2 that pass guard a fresh install and doctor ([output](../evidence/7.10/failing-before.txt)); after: 368 pass, and the type check passes ([output](../evidence/7.10/test-output.txt))
- How it works: a planned file can carry a `pointer` (a marker plus lines). If the file exists and already contains the marker (`@AGENTS.md` for CLAUDE.md, `.groundwork/HANDOFF.md` for AGENTS.md), it's left alone. If it exists without the marker, only the pointer line is appended. If it doesn't exist, it gets the full template. This also applies to `groundwork adapter add`.
- Found during implementation: without the marker, running `init` twice appended the pointer to Groundwork's own AGENTS.md, since its rule 1 is worded differently. The existing "doesn't ask about identical files" test caught it.
- `KEPT_ADVICE` and `keptAdvice` were removed: they only covered these two files, so they could no longer produce output.
- Three tests in `init.test.ts` pinned the old overwrite prompt for these two files. They now test the same prompt on `.groundwork/SPEC.md`, which still asks, so the ask-before-overwrite behavior is still covered.
- README: the `init` row says it never replaces these files.
- Reviewer: all criteria met. Checked against L-006, L-015, L-016, L-017 and L-018.
- Caveats:
  - A CLAUDE.md that Groundwork generated in an older version keeps its old command list, because it already has `@AGENTS.md`. `groundwork upgrade` (card 9.4) should handle it.
