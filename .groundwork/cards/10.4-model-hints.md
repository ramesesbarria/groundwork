## Goal
An optional `models` setting lets adapters run cheaper models for mechanical roles and stronger ones for judgment. Planned changes: PLAN.md §10.4.

## Acceptance criteria
- [x] Empty `models` gives exactly today's output (snapshots unchanged)
- [x] A set value shows up in both adapters' agent files
- [x] The `none` adapter is unaffected

## How to check
Add `"models": { "reviewer": "opus" }` to `.groundwork/config.json`, run `npx groundwork-ai adapter add claude-code`, and `.claude/agents/gw-reviewer.md` gets `model: opus`.

## Evidence
- Tests before: 5 fail ([output](../evidence/10.4/failing-before.txt)); after: 526 pass, and the type check passes ([output](../evidence/10.4/test-output.txt)). The adapter snapshots are unchanged.
- Field formats checked on 2026-09-25: Claude Code subagents take `model:` as an alias (`opus`, `sonnet`, …), a full ID, or `inherit` (code.claude.com/docs/en/sub-agents); OpenCode agents take `provider/model-id` (opencode.ai/docs/agents). Because they differ, a hint is either one string for every tool or an object with one value per adapter.
- The project's `models` setting reaches `adapter add`, `upgrade` and `doctor` through a new `config.ts`. `doctor` compares generated files using the same hints, so there's no false drift, and it suggests a fix for a hint whose role doesn't exist.
- Schema: `models` with the four roles, each a string or a per-adapter object. The 10.2 test caught tool names in the first draft of its description, which were then removed.
- Reviewer: all criteria met. Checked against L-006, L-017 and L-018.
- Caveat: model values are passed through as written. Groundwork doesn't check that a model name exists in the tool.
