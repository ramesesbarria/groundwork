## Goal
`npx groundwork-ai init` installs Groundwork into a project.

## Acceptance criteria
- [x] Copies the core into `.groundwork/` and asks which adapter to install (only Claude Code in v0.1)
- [x] Never overwrites an existing file without asking; `--dry-run` lists what it would write
- [x] Works on Windows and Linux (checked in CI)
- [x] Integration test: run init in a temp folder and check the resulting tree

## Evidence
- Tests before: the init tests fail because `init.ts` doesn't exist ([output](../evidence/2.2/failing-before.txt))
- Tests after: 143 passed ([output](../evidence/2.2/test-output.txt)). One test runs the **built** CLI in a temp folder.
- Build: `tsc` succeeds ([output](../evidence/2.2/build-output.txt))
- End to end: packed the real npm package, installed it in a fresh project, and ran `npx groundwork init`. It created 37 files; a second run changed nothing; with a user's own CLAUDE.md and no terminal it kept their file and said what to add ([output](../evidence/2.2/end-to-end.txt))
- Reviewer (second pass): criteria 1, 2 and 4 met. Checked against L-003 (no new dependencies; uses Node's own readline) and L-006.
  - **Criterion 3:** CI passed on Ubuntu and Windows, Node 22 and 24 ([run 35982839497](https://github.com/ramesesbarria/groundwork/actions/runs/35982839497)).
  - **The interactive prompts were tested with scripted answers, not typed in a real terminal.**
  - Changes beyond the card: `run()` is now async; the package ships `core/` (copied in at pack time); the HANDOFF template's first step is now `gw-setup`, not `gw-spec`; gw-plan names the template paths.
  - First pass sent back: a second run said "installed" when nothing changed. Fixed, but the test for it was written at the same time as the fix, so it was never seen failing first.
