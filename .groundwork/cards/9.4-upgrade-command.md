## Goal
Projects installed with an older version can be brought up to date, and `doctor` says when they're behind. Planned changes: PLAN.md §9.4.

## Acceptance criteria
- [x] An upgrade test: a v0.3-shaped project gets the new core, and its state files are byte-identical afterwards
- [x] `doctor` suggests an upgrade for an old version
- [x] The README limitation about having no upgrade command is removed

## How to check
In a project set up with an older Groundwork, run `npx groundwork-ai doctor` (it suggests an upgrade), then `npx groundwork-ai upgrade --dry-run` to see what would change, then `npx groundwork-ai upgrade`. Your spec, handoff, lessons and cards don't change; `/gw` appears.

## Evidence
- Tests before: the suite can't load because `src/version.ts` doesn't exist yet ([output](../evidence/9.4/failing-before.txt)); after: 443 pass, and the type check passes ([output](../evidence/9.4/test-output.txt))
- End to end on the real published `groundwork-ai@0.3.0`: doctor suggested an upgrade, upgrade asked once, SPEC, HANDOFF, LESSONS and AGENTS.md hashes were unchanged, `gw-resume` and its skill were removed, `/gw` and the session hook were added, and doctor then found no problems ([output](../evidence/9.4/upgrade-real-0.3.0.txt))
- How it works: `init` writes `"version"` into config.json (schema updated). `upgrade` refreshes every core file except the project's own (SPEC, HANDOFF, LESSONS, config, AGENTS.md); removes retired commands and their adapter files; refreshes installed adapters (settings are merged, not replaced); replaces CLAUDE.md only when every line is Groundwork-generated; then stamps the new version, keeping every other config value. It asks once, not per file; `--dry-run` lists the changes.
- `doctor` suggests `groundwork upgrade` when the stamp is missing or older, and its adapter messages point to `upgrade` in that case, since `adapter add` would leave the core behind.
- The `gw-resume` grep test now allows `upgrade.ts` and its test, which name it on purpose to remove it.
- This resolves card 7.10's caveat about stale Groundwork-generated CLAUDE.md files.
- Reviewer: all criteria met. Checked against L-006, L-015 (the npx install ran only after changing into the temp folder), L-016, L-017 and L-018.
- Caveats:
  - The CLI's own version is still 0.3.0, so an upgraded project is stamped 0.3.0 even though its files are newer than the published 0.3.0. Bump the version before the next release.
  - A project's AGENTS.md is its own, so upgrade doesn't bring template changes like rule 9 (cards 7.2, 9.1) into it.
