## Goal
On an existing project you spec the change you want, not the whole app. Planned changes: PLAN.md §9.9.

## Acceptance criteria
- [x] After setup on an existing project, the next step is always a question about what to change
- [x] A change spec includes what must not break
- [x] New-project specs are unaffected

## How to check
Read the "Changes" comment in `core/templates/SPEC.md`, then "Existing project" in `core/commands/gw-spec.md`: it starts with "What do you want to change or add first?".

## Evidence
- Tests before: 8 fail, and 2 guards for the unchanged new-project flow pass ([output](../evidence/9.9/failing-before.txt)); after: 480 pass, and the type check passes ([output](../evidence/9.9/test-output.txt))
- SPEC template: a new "Changes" section; each change has a goal, rules, edge cases and must-not-break, and is marked open, planned or done. It's now a required section in the templates test.
- `gw-spec` has an "Existing project" section. Its numbered steps for new projects are unchanged (tested).
