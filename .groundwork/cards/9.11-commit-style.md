## Goal
Groundwork uses a repo's own commit format instead of forcing `[1.2] Title`. Planned changes: PLAN.md §9.11.

## Acceptance criteria
- [x] The default output is unchanged
- [x] A configured format is used for commits
- [x] A retro test with a custom format still finds signals

## How to check
Set `"commitFormat": "feat: {title} ({id})"` in `.groundwork/config.json`, approve a card, and the commit reads `feat: <title> (<id>)`. `npx groundwork-ai retro` still links later fixes to that card.

## Evidence
- Tests before: 10 fail ([output](../evidence/9.11/failing-before.txt)); after: 498 pass, and the type check passes ([output](../evidence/9.11/test-output.txt))
- `commitFormat` is in the config template, set to today's `[{id}] {title}`, so the default is unchanged. The schema documents `{id}` and `{title}`; quick changes use `quick` as the ID.
- `gw-approve`, `gw-next`, `gw-quick`, the workflow and AGENTS.md rule 5 all point to it, and each still names the default format.
- Existing-project setup proposes a format from `git log`, marked *found*.
- `retro` builds its card-commit matcher from `commitFormat` (new `cardIdPattern`), so fix-after-card signals work with any format. A missing setting falls back to the default.
