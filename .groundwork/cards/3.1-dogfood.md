## Goal
Install Groundwork into its own repo and a small sample app, run one card end to end, and fix what breaks.

## Acceptance criteria
- [ ] **(partly: init → setup → spec → plan → next ran; stopped during card 1.1's implementation. Moved to card 6.1)** `init` run on a fresh sample app, then `gw-spec` → `gw-plan` → `gw-next` → `gw-approve` completes one card
- [ ] **(not done; moved to card 6.1)** Resume test (moved from 1.5): stop partway through a card, open a fresh session (ideally a different tool, e.g. OpenCode + DeepSeek), run `gw-resume`, and it continues without redoing finished steps
- [x] Every problem found is logged in LESSONS.md with its origin
- [x] A short write-up of the run saved as evidence (it becomes the first draft of the README demo)

## Findings so far
- F1 (2026-09-24, install): on Windows, git warns about line endings on all 34 installed files, because `init` doesn't add a `.gitattributes`. Harmless, but noisy on a user's first commit.

- ✅ `gw-setup` worked as designed in a real Claude Code session: all 6 placeholders filled, no stack picked (commands say "not set yet"), `per-phase` chosen, and HANDOFF points to `gw-spec`.
- ✅ The generated skills show up in Claude Code's `/gw` autocomplete (human confirmed). The adapter's files load in real Claude Code.
- Human feedback on setup: nothing felt off.
- F2 (2026-09-24, setup): nothing suggests committing after `gw-setup`, so its changes sit uncommitted until the first card. Minor.

- ✅ `gw-spec` produced a clear, detailed spec. When the human said "your call", it filled gaps with defaults but marked every one *(default)* instead of passing guesses off as decisions.
- ✅ Three decision records (platform, backend, sign-in) with 2–4 options each, pros/cons and switching cost, and **no choice made**. Stack-neutral as designed.
- F3 (2026-09-24, spec): `gw-spec` doesn't say what to do when the human says "you decide". The model improvised well (marking defaults), but it should be written into the command so every model does it.
- F4 (2026-09-24, spec): **no scope check.** A "tiny sample app" grew into a multi-user phone app with households, invites, push notifications, edit history and time zones. `gw-spec` should ask "what's the smallest first version?" and put the rest in later phases. The same pattern as L-003.
- F5 (2026-09-24, plan): HANDOFF is stale. `gw-plan` wrote three decision records and stopped to wait for the human's choices, but didn't update HANDOFF first. It still says the spec is waiting for confirmation. `gw-plan` only updates HANDOFF at its last step; the workflow says to update it before *any* stop.
- F6 (2026-09-24, setup; **found by the model itself**): AGENTS.md rule 5 says "Don't commit until the human approves", which reads like per-card mode even when `per-phase` is set. `gw-setup` spotted it, correctly left the template alone, and told the human.
- F7 (2026-09-24, plan): the human ran `/gw-plan` without confirming the spec (`gw-spec` step 6), and `gw-plan` didn't check. It should notice that HANDOFF says the spec is unconfirmed and ask once.
- ✅ `gw-plan` refused "your call" for stack choices ("the one kind of choice Groundwork won't make for you") and gave "if X matters, choose Y" guidance instead of a pick.
- ✅ `gw-spec` listed the extra defaults it chose beyond the questions it asked, so nothing was hidden.

- ✅ `gw-plan` produced 8 well-formed cards for a local-only phase 1, with sensible `depends_on` (1.2→1.3, 1.4→1.5, 1.6 needs 1.2+1.3+1.5), and wrote later phases into HANDOFF. **But** the scope was only trimmed because the human asked; F4 still stands.
- ✅ Decision 0004 records the human's reply in their own words ("1. a q2 a q3 b") and flags the one thing it defaulted (npm).
- ✅ Tester on card 1.1: tests fail for the right reason (missing modules), output saved as evidence, and HANDOFF includes a precise "contract for implementer". This is the best HANDOFF so far.
- F8 (2026-09-24, tester): card 1.1's manual checks repeat its acceptance criteria almost word for word, doubling the card's length. The tester role should add manual checks only for criteria that can't be automated.
