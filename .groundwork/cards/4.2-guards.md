## Goal
The GUARD level of the ladder: small scripts that block an action, wired into Claude Code hooks.

## Acceptance criteria
- [x] A guard is a Node module in `.groundwork/guards/` exporting `check(action)` → `{ block, reason }`; an action is a shell command or a file write
- [x] A runner turns a tool's hook input into an action, runs the guards listed in `config.json` (`guards: []`), and blocks with the reason
- [x] Built-in guard `no-ai-trailers` blocks commit messages that add AI attribution; it's off unless listed
- [x] The Claude Code adapter adds a `PreToolUse` hook in `.claude/settings.json`; `init` merges into an existing settings file instead of overwriting it
- [x] Tests cover the guard, the runner (allow and block), and the settings merge

## Evidence
- Tests before: fail, modules missing ([output](../evidence/4.2/failing-before.txt)); after: 179 pass ([output](../evidence/4.2/test-output.txt)); build OK ([output](../evidence/4.2/build-output.txt))
- End to end: `init` merged into an existing `.claude/settings.json` (kept the user's permissions); with `no-ai-trailers` on, a simulated Claude Code hook blocked an AI-trailer commit (exit 2) and allowed a normal one ([output](../evidence/4.2/end-to-end.txt))
- Reviewer: all criteria met. Checked against L-001 (this guard is its GUARD level), L-003 and L-006.
  - **Not yet run inside real Claude Code.** The hook command uses `$CLAUDE_PROJECT_DIR`, which assumes Claude Code runs hooks through a shell that expands it (it does through bash; not verified on Windows). If it fails, Claude Code treats it as a non-blocking error, so guards would silently not run. Check in card 6.1.
  - The guard only sees the command text. A message in a file (`git commit -F msg.txt`) isn't checked. A git `commit-msg` hook would close that gap for every tool; left for later.
  - The hook starts Node for every shell command and file write, even with no guards on (it exits right away). Tens of milliseconds each.
  - The snapshot change was reviewed: only the new settings file.
