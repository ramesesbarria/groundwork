## Goal
In Claude Code the agent picks the right Groundwork command from a plain request, and it can never run `gw-approve` or `gw-reject` itself. Planned changes: PLAN.md §7.1.

## Acceptance criteria
- [x] Every command description says *when* to use it, not only what it does
- [x] The generated `gw-approve` and `gw-reject` skills can't be invoked by the model (field verified against the docs; the link goes in Evidence)
- [x] Snapshots updated; the tests still check that the skill description equals the command description
- [x] Without an adapter, `gw-approve` and `gw-reject` still say in their own text that only the human runs them

## Evidence
- Tests before: 19 of the new tests fail ([output](../evidence/7.1/failing-before.txt)); after: 318 pass, and the type check passes ([output](../evidence/7.1/test-output.txt))
- Field: `disable-model-invocation: true`, from https://code.claude.com/docs/en/skills (checked 2026-09-24). The docs say it keeps the description out of the model's context and blocks the model from invoking the skill, while `/name` still works for the user.
- OpenCode: https://opencode.ai/docs/commands/ lists only `description`, `agent`, `model` and `subtask`, so there's no equivalent. Recorded under Honest limitations in the README.
- The snapshot diff has only the new descriptions plus `disable-model-invocation: true` on the two skills. The equality test in `claude-code.test.ts` is unchanged. The `gw-next` description was reworded without quote marks so that test still compares plain strings.
- Reviewer: all criteria met. Checked against L-006 (no claim beyond what's tested), L-014, L-017 (grepped for copies of the old descriptions: none outside the command files, tests and snapshots) and L-018.
- Caveats:
  - Not yet tried in a live Claude Code session. The tests check the generated file, not Claude Code's behavior.
  - In Claude Code, "approve it" in plain words no longer loads the skill: the human types `/gw-approve`. That's intended, but worth knowing.
  - Skill descriptions are a little longer, which adds a few tokens to what Claude Code always loads.
  - One markdown edit in the core files was made with `sed` rather than the edit tool (L-014 is about code; no escapes were involved and the result was checked).
