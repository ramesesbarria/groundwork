## Goal
Someone on Node 18 or 20 gets a plain "Groundwork needs Node 22 or later" message, not a stack trace. Planned changes: PLAN.md §7.9.

## Acceptance criteria
- [x] A test with a stubbed version gets the plain message and exit code 1

## How to check
With Node 20 installed (e.g. through nvm), run `npx groundwork-ai@latest --version`. You'll see one line telling you to install Node 22 from nodejs.org.

## Evidence
- Tests before: the suite can't load because `src/node-version.ts` doesn't exist yet, which is the missing feature ([output](../evidence/7.9/failing-before.txt)); after: 362 pass, and the type check passes ([output](../evidence/7.9/test-output.txt))
- The end-to-end test runs the built `dist/bin.js` in a child process with `process.versions.node` stubbed to 20.11.1 before anything loads: stderr is exactly the message, stdout is empty, and the exit code is 1. With 22.12.0 it runs normally.
- `bin.ts` checks first and loads the rest of the CLI with a dynamic `import()`, so nothing that needs Node 22 is parsed on an old version. The compiled check (`dist/node-version.js`) uses nothing newer than Node 18.
- Reviewer: all criteria met. Checked against L-006 and L-018.
- Caveats: not run on a real Node 20 install, only with the version stubbed. Node versions older than 14.8 can't parse `bin.js` at all, but those are long out of support.
