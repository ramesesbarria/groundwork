## Goal
The escalation ladder in action (SPEC §9): find repeated mistakes and propose promoting them.

## Acceptance criteria
- [x] `groundwork retro` collects signals from git and `.groundwork/`: reverts, fix commits soon after a card, rejections, and reviewer send-backs
- [x] It prints a plain report grouping similar signals, with counts and sources
- [x] `/gw-retro` reads the report and proposes ladder changes; nothing changes without the human's OK
- [x] Tests run retro against a fixture repo with known signals

## Evidence
- Tests before: the test file failed to load because `gw-retro.md` didn't exist, so the CLI tests never ran red individually ([output](../evidence/5.2/failing-before.txt)); after: 270 pass ([output](../evidence/5.2/test-output.txt)); build OK ([output](../evidence/5.2/build-output.txt))
- **Real use:** `groundwork retro` on this repo found 5 review send-backs and 1 fix after a card ([report](../evidence/5.2/retro-on-this-repo.md)). **3 of the 5 send-backs share one cause: one core file contradicted another** (cards 1.2, 1.3, 1.4). This is a candidate for a new lesson, left for the human to accept via `/gw-retro`, as its own rules require.
- Reviewer: all criteria met. Checked against L-003, L-006.
  - Grouping is by type and by the lesson IDs cited. Grouping *differently worded* signals about the same mistake is left to `/gw-retro` (a judgment call, so it's the agent's job, not the CLI's).
  - "Fix soon after a card" = a commit with "fix" in its subject within 5 commits of a card commit, touching that card's files. It counts other cards' fix commits too (here, 3.2's dogfood fixes to 2.2's `init.ts`), which is fair but can be noisy.
  - `retro` writes `.groundwork/retro.md` in the project; this repo's copy was moved into evidence.
