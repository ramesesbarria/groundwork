# Groundwork v2

What Groundwork 2.0 does, what it guarantees, and where it stops. This is also the design record
for the change from 1.0.

**Status: released as `groundwork-ai@2.0.0` on 2026-11-15.** See [Before release](#before-release).

## Why 2.0

After real use, the part of Groundwork that earned its keep was project context: continuity across
sessions, tools, models and parallel agents. The prescribed build loop (spec, cards, three roles,
approval gates) was the part other projects left out. 1.0 also had gaps in the part that mattered:

- Every write to the handoff depended on the model remembering, at the moment its context was lowest.
- The handoff had no time, commit, branch or author, so a stale one looked like a fresh one.
- Its fields assumed a card. Parsing was two copies of one regex. Nothing bounded its size.
- A session start injected three lines. Nothing compared them with the repository.

2.0 keeps the name, the package (`groundwork-ai`), the `groundwork` binary, the `.groundwork/` folder
and the `/gw` commands, and changes what is in front:

**Project memory for coding agents: any session, tool or model resumes where the last one stopped.**

The context layer is the product and the default install. The development flow is an add-on on top.

## What 2.0 guarantees

1. **Context-only by default.** `groundwork init` installs only the context layer. With the flow
   off, no installed file and no text a session is given mentions cards, roles or approvals. A test
   scans every installed file for each adapter, and the brief, the hooks' messages, `status` and
   `doctor`.
2. **The flow is opt-in and reversible.** `init --flow` or `flow on` adds it; `flow off` removes
   Groundwork's own flow files and keeps what the project made. The choice is `flow` in `config.json`.
3. **One parser and serializer.** `core/lib/memory.mjs` reads and writes every memory file. The CLI
   loads it from its own core; the hooks load the copy installed in `.groundwork/lib/`. No command
   or hook parses a handoff field itself (a test checks).
4. **The CLI writes the facts.** `checkpoint` stamps time, commit, branch, uncommitted file count,
   tool, model and session, and derives the journal entry from git. The agent supplies only prose.
5. **A handoff is never taken on trust.** Every load compares its stamp with the repository and
   gives one verdict with the concrete delta: `brief`, the session-start hook, `status`, `doctor`.
6. **An automatic checkpoint never claims what it doesn't know.** A hook does not restamp a handoff
   nobody touched: it stays `behind`, and the agent is asked to save it.
7. **Memory hooks never block work.** They always exit 0, set no `onFailure`, give up after 8
   seconds, and ask the agent at most once per commit.
8. **Nothing is deleted.** `compact` moves material to `.groundwork/archive/`; converting an old
   handoff keeps every field; `upgrade` never touches the project's own files.
9. **One writer per handoff.** The root handoff belongs to the main checkout. A linked worktree, a
   task branch or a named worker gets its own file, so parallel work never conflicts in git.
10. **1.x installs keep everything.** `upgrade` leaves the flow on, and adds the context layer
    underneath.
11. **With the flow on, 1.0's contract holds.** Guards, approvals, cards, `check` and the commit
    gate behave as [V1.md](V1.md) says. No guard is weaker; three protections were added.

## Handoff schema

```markdown
---
schema: 2
updated: 2026-11-15T10:02:11Z
head: 0b6a44d1c0e5…            (full commit hash)
branch: main
dirty: 2                        (uncommitted files, not counting .groundwork/)
tool: claude-code               (when known)
model: …                        (when known)
session: …                      (when known)
worker: auth-tests              (worker handoffs only)
state: active | done            (worker handoffs only)
body: 3f6f3520fb5c              (fingerprint of the prose)
deps: map=… decisions=… lessons=…   (fingerprints of the memory it was written against)
---
# Handoff

## Now
## Next
## Blockers
## Failing checks
## Workers in flight
## Notes
## Flow                         (flow only: the Phase, Current card and Status bullets)
```

- The frontmatter is the machine-readable form; `brief --json` gives the parsed whole.
- `checkpoint` writes every frontmatter key. Nobody types them.
- **Now** and **Next** are required. An empty section is written as `none`.
- A handoff from before 2.0 (bullets such as `- **Next step:**`) is read through the same fields:
  `Last step`→Now, `Next step`→Next, `Failing checks`, `Workers in flight`, `Notes`. An explicit
  `checkpoint` or `compact` rewrites it in this layout; bullets with no section of their own go under
  Flow (flow on) or Notes, and unknown `##` sections are kept until `compact` archives them.
- `doctor` fails a 2.0 handoff with no Now or Next, a `head` that isn't a hash, or a wrong `schema`.
  A pre-2.0 layout and a missing stamp are suggestions, so an upgraded project isn't failed.

## Commands

Run as `npx groundwork-ai <command>`.

| Command | Flags | What it does |
|---|---|---|
| `init` | `--adapter claude-code\|opencode\|codex\|cursor\|gemini\|none` (one, or several separated by commas), `--flow`, `--dry-run` | Install the context layer; with `--flow`, the flow too |
| `brief` | `--json`, `--budget <tokens>`, `--worker <id>`, `--root` | Print the resume context inside a token budget |
| `checkpoint` | `--now`, `--next`, `--blockers`, `--failing`, `--workers`, `--notes`, `--note`, `--worker <id>`, `--root`, `--tool`, `--model`, `--session`, `--json` | Save and stamp the handoff; append the journal entry |
| `status` | | Now, Next, freshness, workers in flight (saved or not yet); with the flow, cards |
| `decide` | `"<title>"`, `--status` | Create the next decision record; update the index |
| `lesson` | `"<name>"`, `--origin`, `--level NOTE\|RULE` | Add the next lesson |
| `index` | `--check` | Regenerate `DECISIONS.md` |
| `worker` | `start <id> [--goal] [--branch]`, `done <id> [--outcome]`, `list [--json]` | Record parallel workers. `list` shows worker handoffs, and in its text output also workers started but not yet saved (`--json` is handoffs only) |
| `compact` | `--dry-run` | Archive journal entries beyond the budget, every superseded decision, and handoff sections Groundwork doesn't define |
| `doctor` | | Install, memory, budgets; exits 1 on problems |
| `upgrade` | `--dry-run`, `--yes` | Update Groundwork's files; keep the project's layers and state |
| `adapter` | `add claude-code\|opencode\|codex\|cursor\|gemini` | Add or refresh an adapter |
| `flow` | `on`, `off`, `--yes` | Show, add or remove the flow |
| `uninstall` | `--dry-run`, `--keep-state` | Remove what Groundwork added |
| `mode`, `check`, `reassess`, `migrate`, `retro` | as in 1.0 | The flow's commands |

`checkpoint` in detail:

- With section flags it replaces those sections and keeps the others. With none, it stamps the file
  as it is, so editing the handoff and running `checkpoint` is the other way to save.
- It refuses (exit 1) to stamp a handoff nobody has written.
- It warns when it restamps text that is unchanged since an older commit.
- The journal entry lists the commits and files since the journal's last entry. The journal has its
  own cursor (the commit in its last entry's heading), so commits are recorded even while the
  handoff's prose lags. No commits, no entry, unless `--note` is given. Worker checkpoints don't
  write the journal.
- The writer is taken from the flags, then `GROUNDWORK_TOOL` / `GROUNDWORK_MODEL` /
  `GROUNDWORK_SESSION`, then `CLAUDECODE=1`, then the session the session-start hook recorded in
  `.state.json` within the last 12 hours.

## Freshness

`assess` in `core/lib/freshness.mjs`. One verdict, in this order of precedence:

- **diverged**: the stamped commit no longer exists, or isn't an ancestor of HEAD (rebase, reset,
  another branch). When there is a merge base, both sides are counted and the commits after the
  split are listed.
- **stale**: older than `staleAfterDays` (default 14). If it is also behind, the delta is still given.
- **behind**: the stamped commit is an ancestor of HEAD and commits landed since. Up to 8 are listed,
  with the files that changed.
- **fresh**: written at HEAD, or only `.groundwork/` changed since.
- **unstamped**: no `updated` and no `head`. There is nothing to compare.

Notes added to any verdict: the branch changed since the stamp; files the Now and Next sections
name are among the changed files; the map, the decisions or the lessons changed since the stamp
(the dependency fingerprints, promoted from the team prototype's `context.json`); uncommitted files.

Commits that touch only `.groundwork/` are not counted, so committing the handoff doesn't make it
behind. Without git, only age is checked.

## Hooks

Core scripts, tool-neutral:

- `hooks/session-start.mjs [project] [tool]` prints the brief. Hook input on stdin (`session_id`,
  `model`, `source`) is remembered in `.state.json`. After a compaction it adds a line telling the
  session to trust memory over what it recalls.
- `hooks/checkpoint.mjs <stop|pre-compact|session-end> [project] [tool] [--block-json]` runs an
  automatic checkpoint, then:
  - `stop`: if the handoff is behind, diverged, unstamped, or empty with uncommitted work, it asks
    the agent to save. Once per commit (the key is in `.state.json`), never when the input says
    `stop_hook_active`, never with `"nudge": false`.
  - `pre-compact`: prints what the compaction summary must keep.
  - `session-end`: prints nothing.

Per adapter:

| Event | Claude Code (`.claude/settings.json`) | OpenCode (plugin) |
|---|---|---|
| Session start | `SessionStart`, matcher `startup\|resume\|clear\|compact`; stdout becomes context | `session.hook("context")`: the brief is pushed onto `system`, rebuilt at most every 15 s |
| Turn ends | `Stop`, `--block-json`: `{"decision":"block","reason"}` reaches the model; timeout 15 s | `event.subscribe({ types: ["session.idle"] })`; the reminder rides on the next `context` call |
| Before compaction | `PreCompact`; stdout becomes summary instructions; timeout 15 s | `session.hook("compaction")`: instructions pushed onto `system` |
| Session ends | `SessionEnd`; timeout 10 s (the default budget is 1.5 s) | none: OpenCode has no session-end hook |
| Flow only | `PreToolUse` (guards, `onFailure: "block"`), `UserPromptSubmit` (approval recorder) | `tool.hook("execute.before")`, `session.hook("prompt")` |

The Codex, Cursor and Gemini CLI adapters wire the same three scripts into each tool's own events.
Each adapter's page in the docs (`docs/content/docs/adapters/`) has the full list; what each does
and does not do:

| | Codex | Cursor | Gemini CLI |
|---|---|---|---|
| Session start | `SessionStart` (startup, resume, clear, compact, fork); plain stdout becomes context | `sessionStart`, once per conversation; `additional_context`. A resumed or compacted conversation isn't documented to run it again, so `AGENTS.md` says to run `brief` | `SessionStart` (startup, resume, clear); `additionalContext`. No compaction source is documented |
| Turn ends | `Stop`: continues with the reminder as a new prompt | `stop`: `followup_message` | `AfterAgent`: `{"decision":"deny","reason"}` retries with the reminder |
| Before compaction | `PreCompact`: checkpoint only (stdout is ignored, so the summary isn't told what to keep) | `preCompact`: checkpoint only | `PreCompress`: checkpoint only |
| Session ends | `SessionEnd` (timeout 3 s) | `sessionEnd` | `SessionEnd` (best effort) |
| Commands | `$gw` skills in `.agents/skills` | `/gw` skills in `.cursor/skills` | `/gw` TOML commands in `.gemini/commands`; `GEMINI.md` imports `AGENTS.md` |
| Flow guard | `PreToolUse` for `Bash` and `apply_patch`; not fail-closed | `beforeShellExecution` with `failClosed`; file writes not guarded | `BeforeTool` for shell, `write_file`, `replace`; not fail-closed |
| Flow approvals | Not bound to the human's message (no recorder); `gw-approve` and `gw-reject` are explicit-invocation only | No recorder; the approve and reject skills are `disable-model-invocation` | No recorder; the commands are not marked human-only |

For all three the adapter follows the tool's documentation, read on 2026-11-15, and has not been run
inside the tool. The flow's limits for each are printed by `init --flow`, `adapter add` and
`flow on`.

Claude Code event names, inputs and outputs were checked against code.claude.com/docs/en/hooks on
2026-11-15. OpenCode's `compaction` hook and `event.subscribe` were read from
opencode.ai/v2/docs/build/plugins/server and its v1 migration guide on the same day.

Measured on Windows 11, Node 24: stop 1.2 s, session start 0.8 s, session end 0.4 s. Most of it is
starting git, which is why one `git status --porcelain=v2 --branch` answers commit, branch and
uncommitted files, and why a hook process asks each question once.

## Budgets

`budgets` in `config.json`, in estimated tokens (characters ÷ 4):

| Key | Default | Over budget |
|---|---|---|
| `brief` | 1500 | The brief cuts itself to fit; `doctor` fails above 125% |
| `handoff` | 600 | `doctor` fails; `compact` archives sections a handoff doesn't define |
| `map` | 800 | `doctor` fails; shorten it by hand |
| `decisions` | 600 | `doctor` fails; `compact` archives superseded records (it does so whether or not this is over budget) |
| `lessons` | 1200 | `doctor` fails; merge or drop by hand |
| `journal` | 2500 | `doctor` fails; `compact` archives the oldest entries |

`tokenBudget` (2000) is unchanged from 1.0: what is always loaded (`AGENTS.md`, `CLAUDE.md`, skill
and subagent lists). The session-start text is no longer part of it; it has `budgets.brief`.

The brief gives the handoff the largest share, then the map, decisions, rules and workers; a part
that needs less than its share gives the rest away. Cut parts end with a pointer to the file.
`doctor` also checks that `DECISIONS.md` is in step, that `MAP.md` exists, is filled in and names
paths that exist, and that a RULE lesson is cited in `AGENTS.md`.

`compact` moves, never deletes. Only the journal is gated by its budget: it keeps the newest entries
that fit and archives the older ones. Superseded decisions are archived every time `compact` runs,
whether or not `decisions` is over budget, because a superseded record isn't in force and has no
place in the brief; handoff sections Groundwork doesn't define are archived the same way. So journal
entries go to `archive/JOURNAL-<year>.md`, superseded decisions
to `archive/decisions/`, unknown handoff sections (with the whole previous handoff) to
`archive/HANDOFF-<date>.md`. It doesn't shorten Now, Next or Notes: only a person or an agent can
judge those, and it says so.

## Parallel workers

- **Which handoff.** In order: `--worker <id>` or `GROUNDWORK_WORKER`; a
  `.groundwork/work/<branch-as-slug>/HANDOFF.md` that exists (also `work/<id>/` on a 1.x `gw/<id>`
  branch); a linked git worktree, which is always a worker named after its branch; else the root.
- **Single writer.** Only the main checkout's session writes the root handoff. `worker start` and
  `worker done` are refused in a linked worktree. Worker checkpoints write neither the root handoff
  nor the journal.
- **Workers in flight.** `worker start <id>` adds a line to that section of the root handoff and a
  row to `work/LEDGER.md`; `worker done <id>` removes the line, logs the outcome and sets the
  worker's `state: done`. The brief and `status` list active workers with their own next step.
- **Writes.** A checkpoint takes `.groundwork/.lock` (a stale lock is taken over after 15 s) and
  writes through a temporary file and a rename. An automatic checkpoint stands back if the lock is
  held; an explicit one writes anyway and warns.
- **Conflicting writers.** If a different session stamped the same handoff within 30 minutes,
  `checkpoint` warns and says to give one of them a worker id. It still writes: nothing in the
  context layer blocks.

The ledger and the Workers in flight field come from a project that had hand-rolled both.

## Upgrading from 1.x

`npx groundwork-ai upgrade`:

- The flow stays on. A config with no `flow` key counts as on wherever the flow's files are, and
  the upgrade writes `flow: true`.
- Added to `config.json`: `flow`, `budgets`, `staleAfterDays`, `nudge`. No flow setting is added or
  changed.
- Created if missing: `MAP.md`, `DECISIONS.md` (generated from the existing records), and the
  context layer's library, hooks and `memory.md`. Managed files are replaced unless edited, as in
  1.0 (`<file>.new` next to an edited one).
- Never touched: `HANDOFF.md`, `SPEC.md`, `LESSONS.md`, `JOURNAL.md`, cards, decisions, evidence,
  rules, `AGENTS.md`, `CLAUDE.md`, config values.
- Claude Code's `SessionStart` entry is replaced in place (its command is the one 1.x wrote), and
  `Stop`, `PreCompact` and `SessionEnd` are added. The user's own hooks and settings stay.
- The old handoff reads as `unstamped`. The first `checkpoint` converts and stamps it.

## The flow

With the flow on, [V1.md](V1.md) is the contract. What changed for it in 2.0:

- `/gw` and the roles read the same files. `gw-handoff` saves through `checkpoint` and keeps the
  Phase, Current card and Status bullets under `## Flow`.
- The codebase map is `.groundwork/MAP.md`.
- The session start is the brief, with the 1.0 lines in it ("Groundwork: card … is being built",
  "Type /gw to continue (the only other commands: /gw-approve, /gw-reject)").
- The guard also locks `.groundwork/lib/` (the hooks import it), refuses the agent's `flow off`,
  and counts `flow: false` in `config.json` as weakening the setup.
- The commit gate lets the files the context layer keeps (journal, map, decisions index, worker
  ledger, handoff and journal archives) ride along wherever the handoff already could, in `[docs]`
  and `[plan]` commits; archived decisions count as planning records, like the decisions. Cards,
  evidence, the spec and decision records are restricted exactly as before, and none of the memory
  files is part of what an approval is bound to.
- `flow off` is a human command. It removes the guards; that is its purpose.

## Adapter contract

What an adapter must do in 2.0. `cli/src/adapters/` holds five
implementations (Claude Code, OpenCode, Codex, Cursor, Gemini CLI); each is a pure function `(core, models, flow) → { path: content }`.

1. **Session start.** When a session starts, resumes, is cleared or compacted, give the model the
   output of `node .groundwork/hooks/session-start.mjs <project> [tool]` (or call its exported
   `orientation(project, { source })`). Pass the tool's hook input on stdin if it has a session id
   or model name.
2. **Checkpoints.** Run `node .groundwork/hooks/checkpoint.mjs <event> <project> <tool>` (or call
   `onEvent(project, event, { tool, session, model, continuing })`) for whichever of `stop`,
   `pre-compact` and `session-end` the tool has. Deliver `say` to the model where the tool allows:
   for `stop` as a continue-with-this-message (`--block-json` prints the JSON shape for tools that
   use it), for `pre-compact` as summary instructions. Pass `continuing: true` when the tool is
   already continuing because of this hook.
3. **Never block.** No fail-closed setting on these hooks, a timeout of 15 seconds or less.
4. **Commands.** Expose each file in the project's `.groundwork/commands/` that `commandsOf` returns
   (`gw`; with the flow also `gw-approve`, `gw-reject`) as a native command that reads the file.
5. **No adapter needed.** With none, `AGENTS.md` tells the agent to run `npx groundwork-ai brief`
   and to save with `checkpoint`.
6. **With the flow** (`flow === true`), as in 1.0: a subagent per role in `subagentRolesOf(core)`;
   the guard runner before every shell command and file write, failing closed; the human-message
   recorder on a hook the agent's own actions never trigger; `gw-approve` and `gw-reject` not
   invocable by the model.
7. **Generated files** must be deterministic and listed by `planAdapter`, so `upgrade`, `doctor`,
   `flow` and `uninstall` can tell them from the user's.

## Supported environments

As 1.0: Node.js 22 or later and Git, on Windows and Linux; Claude Code 2.1.295 or later for the
flow's fail-closed guard (the memory hooks need no minimum beyond the hook events above); OpenCode
2.x; Codex CLI, Cursor and Gemini CLI through their adapters (Gemini CLI with a paid API key: Google's
docs say it was replaced by Antigravity CLI for other users, which has no adapter); any other tool
through `AGENTS.md`. macOS is untested.

## Known limitations

- **Freshness is about the repository, not the truth.** A handoff stamped at HEAD is `fresh` even
  if its prose is wrong. An explicit `checkpoint` with no changes restamps it on the agent's word.
- **The stop reminder is a nudge.** The model can stop anyway, and Claude Code caps consecutive
  continuations. `"nudge": false` turns it off.
- **OpenCode's checkpoint hooks are unverified against a live OpenCode.** They follow the 2.x plugin
  documentation. The payload of `session.idle` isn't documented, so the plugin doesn't read it; each
  registration is isolated, and a missing one leaves the brief and the guards working.
- **A hook can't speak at session end**, and a session that is killed runs no hook: the journal then
  gets its entry at the next session's first checkpoint, and the brief says the handoff is behind.
- **Paths in prose are found by pattern.** "Files its Now/Next sections name" catches backticked
  paths and bare ones with a slash or a 2–5 letter extension.
- **Token counts are estimates** (characters ÷ 4).
- **Windows git is slow to start.** Hooks take about a second there.
- **`npx groundwork-ai` in a project without the package installed** fetches it on first use. The
  hooks don't: they run the scripts in `.groundwork/`.
- **Coarse command matching**, inherited from the flow's guard: with the flow on, a `checkpoint`
  whose text contains the word `migrate` or `uninstall` is refused. Edit the handoff and run
  `checkpoint` with no text instead.
- **A linked worktree is always a worker.** Someone who works alone in one gets
  `work/<branch>/HANDOFF.md`; `--root` writes the root handoff.
- **`flow off` leaves `AGENTS.md` alone**, so its "How we work" still describes the flow until
  edited. It says so.

## Not yet observed

- A real session in Claude Code, OpenCode, Codex, Cursor or Gemini CLI on this build: the hooks were
  run as processes with the documented input, and the OpenCode plugin was mounted with a mock context.
  The Codex, Cursor and Gemini CLI adapters were built from each tool's documentation and tested
  against the files and scripts they generate, never inside the tool.
- A compaction with the summary instructions in place.
- Two live sessions writing one handoff.
- The comparative evaluation on 2.0. [evals/RESULTS.md](evals/RESULTS.md) is 1.0's.

## Open questions after 2.0

- Should `checkpoint` refuse, not warn, when another live session holds the root handoff?
- Should a commit that only adds adapter files (`.claude/`, `AGENTS.md`) count toward `behind`?
- A `map` command that drafts `MAP.md` from the repository, instead of leaving it to the agent.
- Whether the flow's `SPEC.md` Codebase map section in upgraded projects should be moved to `MAP.md`
  by `upgrade`.
- Antigravity CLI, which replaced Gemini CLI for some users, has no adapter.
- Whether the Codex, Cursor and Gemini CLI flow guards can be made fail-closed or bound to the human's
  message once those tools document the behaviour.
