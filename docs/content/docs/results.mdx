<Callout type="warn" title="Measured on 1.0, not on 2.0">
This was run on Groundwork 1.0, with the flow on. It has not been rerun for 2.0, so it says nothing
about project memory alone.
</Callout>

We ran the same agent on the same tasks, with and without Groundwork, and scored every run with
tests the agent never saw.

**What was tested:** OpenCode 2.0.32 with DeepSeek Flash, October 2026. 10 solo tasks and 3 team
scenarios on a small Node.js project, 3 runs each. One agent and model can't show how others behave.

## What it showed

- **Work that spans sessions held together better:** 13 of 15 runs with Groundwork, 7 of 15 without.
- **Work that fits in one session didn't improve:** both solved all 12.
- **It costs more:** about 4× the API cost and 3× the time per solo task.

| | Without | With Groundwork |
|---|---|---|
| Multi-session tasks (5 tasks × 3 runs) | 7/15 | **13/15** |
| Single-session tasks (4 × 3) | 12/12 | 12/12 |
| All solo tasks (10 × 3) | 22/30 | **28/30** |
| Team scenarios (3 × 3) | 9/9 | 9/9 |
| Median API cost per solo run | $0.021 | $0.091 |
| Median time per solo run | 138 s | 389 s |

With three runs per task the differences are suggestive, not conclusive (multi-session p = 0.05,
all solo tasks p = 0.08, Fisher's exact test).

## What it doesn't show

- Project memory alone, or anything about 2.0.
- Other agents or models.
- Savings over a long project. Every task was 1 to 3 sessions on a small codebase.

## One correction

Three bugs in the test harness, not in Groundwork, affected some Groundwork runs. Those runs were
rerun on the same build and every original run is kept. First scored, Groundwork was 24/30;
corrected, 28/30. The baseline was 22/30 either way.
