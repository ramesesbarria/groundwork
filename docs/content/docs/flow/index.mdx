---
title: "The flow (optional)"
description: "A guided way to build on top of project memory: a spec, small cards with proof, and your approval before each commit."
---

The flow is a guided way to build. Your idea becomes a spec, the spec becomes small cards, and each
card is tested, built and reviewed before it reaches you. Nothing is committed without its proof and
your OK.

It is optional. Project memory works without it.

## Turn it on or off

```bash
npx groundwork-ai init --flow      # with a new install
npx groundwork-ai flow on          # add it later
npx groundwork-ai flow off         # remove it
npx groundwork-ai flow             # show which
```

`flow off` keeps what you made: the spec, cards, evidence and rules. Only you can run it; the agent
is refused. It leaves `AGENTS.md` alone, so edit its "How we work" section yourself.

## What you get

| | |
|---|---|
| **A spec** | `.groundwork/SPEC.md`, written from your answers |
| **A plan** | Phases of small [cards](/docs/flow/cards-and-phases), each with a checklist for "done" |
| **A [build loop](/docs/flow/the-build-loop)** | A tester, an implementer and a reviewer take each card in turn |
| **[Proof and approval](/docs/flow/evidence-and-approval)** | A card is committed only with its evidence and your `/gw-approve` |
| **[Right-sizing](/docs/flow/right-sizing)** | A typo takes the quick path; a feature gets a plan |
| **[Team review](/docs/flow/pull-requests)** | Pull-request review can be the approval |

## How you use it

Type `/gw`. It sets the project up, asks about what you want to build, writes the plan, and builds
one card at a time. At each stop you type `/gw-approve`, or `/gw-reject` with a reason.

![An OpenCode session with the flow on: /gw sets the project up, interviews for the spec, and writes the plan of cards.](https://ramesesbarria.github.io/groundwork/demo-first-session.gif)

*Recorded on 1.0. The commands and card steps are the same today.*

## It shares your project memory

The flow uses the same handoff, map, decisions and journal. The handoff gains a `## Flow` section
with the phase, the current card and its status, and the brief says which card is in progress.
