<Callout type="info" title="The flow (optional)">
Project memory works without this. Turn the flow on with `npx groundwork-ai flow on`.
</Callout>

You choose how often the agent stops for you.

| Mode | What happens |
|---|---|
| **`per-card`** (default) | The agent stops after every card. You approve or reject before its commit |
| **`per-phase`** | Cards that pass review are committed. You review the whole phase at its end |
| **`at-end`** | Parked. Projects already using it keep working; it isn't offered to new ones |

Setup asks which you want. To change it later, run it yourself:

```bash
npx groundwork-ai mode per-phase   # or per-card; with no mode it shows the current one
```

The agent can't loosen the mode for you. It can always switch back to `per-card`.

## What every stop shows

1. **What changed**, in terms of what the work does.
2. **How to check it yourself**: a URL, a command, or a thing to click.
3. **The caveats**: anything unverified, partial, or beyond the card.

In `per-phase` mode the review also lists every judgment call the agent made, from the cards' History:
`YYYY-MM-DD call: <what> — <why> — <cost if wrong>`.

## Approving

```text
/gw-approve          when exactly one card is waiting
/gw-approve 1.2      that card (or several ids)
```

Only your own `/gw-approve`, at the start of your message, counts. "Looks good" doesn't, and neither
does a line the agent writes. If anything changes after you approve, you are shown the change and
asked again. [What is enforced →](/docs/flow/evidence-and-approval)

After approval the card is marked `done`, the handoff is updated, and the card's files are committed
as `[<card-id>] <card title>`. When a phase closes, a short recap goes into the journal. The agent
pushes only when you ask.

## Rejecting

```text
/gw-reject results leak before the vote closes
```

The reason is recorded on the card and the work goes back to the implementer. Rejections feed
`groundwork retro`, so a repeated mistake can become a [lesson](/docs/concepts/lessons-ledger).

## Committing yourself

Set `"autoCommit": false` in `.groundwork/config.json`. The agent then tells you what to commit.

## `at-end` (parked)

For projects that already use it: the agent builds every card in order without stopping and commits
each as a checkpoint marked *(not reviewed yet)*. One review covers them all at the end, and you
approve once with `/gw-approve all`.

In a team project, pull-request review is the approval:
[Teams and pull requests](/docs/flow/pull-requests).
