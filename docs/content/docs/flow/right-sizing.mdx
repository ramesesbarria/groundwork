A typo shouldn't need a plan, and a feature shouldn't be built without one. The agent says which path
it is taking before it starts. You can overrule it.

| Path | Use for | What you get |
|---|---|---|
| **Try** | "Can X do Y?" | An answer. No code is merged |
| **Quick** | A typo, a copy tweak, a config value, a small fix | One pass, no card. Checks still run |
| **Card** | A feature, or anything users will notice | The full [build loop](/docs/flow/the-build-loop), with evidence and your approval |

## Try

The agent states the question, tries it on a throwaway branch (`try/<topic>`) or in a scratch folder,
and reports the answer with its evidence. The code is never merged. To keep it, make a card.

## Quick

1. The agent says what it will change and why it is small.
2. If behaviour changes, a test is added or updated first and seen to fail.
3. It makes the change. Test, lint and build must pass.
4. You see a summary, and it commits as `[quick] <what changed>`, with your OK in `per-card` mode.

**Bugs go cause-first.** Reproduce it with a failing test, state the cause in one sentence, then fix
it. After two attempts with no cause, the agent stops and suggests a card.

**It stops being quick** when the change passes about 3 files, or touches what people notice, the
data model, a public API, security or money. The agent then suggests a card.

## Card

Everything else: features, behaviour changes, security, money, anything needing a stack decision,
and UI work, which gets a [UI spec](/docs/flow/ui-and-animation) first.
