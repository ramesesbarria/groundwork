## Is this another framework to learn?

No. There is one command to remember: `/gw`. Groundwork is markdown files, a small CLI and a few
hooks. No server, no account, no lock-in.

## Which AI tools work?

Claude Code, OpenCode, Codex, Cursor and Gemini CLI have adapters that load the brief and add `/gw`.
Any other tool reads `AGENTS.md`, which tells the agent to run `npx groundwork-ai brief` first.
[Other tools](/docs/adapters/other-tools).

## Do the hooks work in my tool?

They are built to each tool's documentation and tested as processes, but not yet run inside a live
session of any of the five tools. If a session doesn't show the brief, run `npx groundwork-ai brief`.

## How do I know the handoff is current?

The brief opens with a verdict: `fresh`, `behind`, `diverged`, `stale` or `unstamped`, with the
commits and files that changed. [Freshness](/docs/concepts/freshness).

## Can it say fresh and still be wrong?

Yes. The verdict compares the handoff with the repository, not with the truth. A handoff saved at
the current commit is `fresh` even if what it says is wrong.

## Will it block me or my agent?

No. The memory hooks never block work. At most they remind the agent to save, once per commit;
`"nudge": false` in `config.json` turns that off. The optional flow is different: its guards can
refuse a commit, on purpose.

## Will it commit or push for me?

Memory never commits or pushes. With the flow on, a card is committed after you approve it, and
`"autoCommit": false` leaves every commit to you. Nothing is pushed unless you ask.

## Does it work on a project that already has code?

Yes. The first `/gw` fills in the map and `AGENTS.md`, and your existing files are never replaced.
[Existing projects](/docs/guides/existing-projects).

## Can I run several agents at once?

Yes. Each worker gets its own handoff, so they never collide in git.
[Parallel agents](/docs/concepts/parallel-agents).

## Can a team use it?

Yes. Commit `.groundwork/` with the code. [Teams](/docs/guides/teams).

## What does it cost in context?

Little, and it is capped. `npx groundwork-ai doctor` shows the numbers for your project.
[What it costs](/docs/concepts/cost).

## Do I need git?

For freshness, yes. Without git only the handoff's age is checked.

## What is the flow, and do I need it?

A guided way to build: a spec, small cards, a tester, an implementer and a reviewer, and your
approval before each commit. Memory works without it. Add it with `npx groundwork-ai flow on`.
[The flow](/docs/flow).

## I'm on 1.x. What happens when I upgrade?

The flow stays on, memory is added underneath, and your own files are never touched.
[Upgrading from 1.x](/docs/getting-started/upgrading).

## How do I remove it?

`npx groundwork-ai uninstall`. It takes out only what Groundwork added, keeps files you changed,
and asks before deleting `.groundwork/`. Don't delete `.claude/`, `.opencode/`, `.codex/`,
`.cursor/` or `.gemini/` by hand: they hold your own settings too.

## Is it ready for real projects?

2.0 is built and tested, but not released. The hooks haven't been run in live sessions yet, and the
[results](/docs/results) are from 1.0.
