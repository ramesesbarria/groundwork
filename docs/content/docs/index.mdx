---

Your AI tool writes the code. Groundwork gives it a process it can't skip, and keeps the state of
the project in files instead of the chat:

<BuildLoopDiagram />

```bash
cd your-project
npx groundwork-ai init      # Claude Code, OpenCode, or plain markdown
```

Then open your AI tool in the project and type `/gw`.

## New in 0.9.0

- **Human checks on cards.** Criteria only a person can judge (a Tab walk, a focus ring, narrow
  layouts) become a `## Human checks` section: `status` and `check` list them, and approval asks you
  to confirm or waive each. They never block a commit.
  [Cards →](/docs/concepts/cards-and-phases)
- **A tighter harness.** `protect-harness` judges shell commands by the files they write, so reads
  no longer block; the commit gate refuses cards over 1,500 tokens until trimmed; evidence links
  that look like patterns (`review-*`) get a clear message.
  [Configuration →](/docs/reference/configuration#enforce)
- **Retro catches every send-back**, including `implementing → testing` and `built → implementing`.
  [Lessons ledger →](/docs/concepts/lessons-ledger)
- From [0.8.1](/docs/adapters/opencode#human-only-commands): OpenCode's commit gate needs a message
  from you since the last commit; subagent prompts don't count.
