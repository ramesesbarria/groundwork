**Project memory for coding agents: any session, tool or model resumes where the last one stopped.**

Groundwork keeps what your project knows in your repo, as plain files: a handoff stamped against git,
a map of the codebase, decisions with an index, lessons, and a journal. Each session starts with a
brief that says where things stand and how far the handoff can be trusted. The CLI writes the facts
(time, commit, branch); the agent writes only the judgment.

<MemoryLoop />

```bash
cd your-project
npx groundwork-ai init      # Claude Code, OpenCode, or plain markdown
```

Then open your AI tool in the project and type `/gw`.

## What project memory is

| File | What it holds |
|---|---|
| [`HANDOFF.md`](/docs/concepts/handoff) | Where things stand, stamped by `checkpoint` |
| [`MAP.md`](/docs/concepts/map) | Where things are in the codebase |
| [`DECISIONS.md`](/docs/concepts/decisions) and `decisions/` | What was decided, and why |
| [`LESSONS.md`](/docs/concepts/lessons-ledger) | What went wrong once and must not again |
| [`JOURNAL.md`](/docs/concepts/journal) | One entry per checkpoint, from git |

Each has a [token budget](/docs/concepts/budgets-and-compaction); `compact` archives, never deletes.

## What is verified, and what isn't

The 2.0 hooks have been run as processes with each tool's documented input, not inside live Claude
Code or OpenCode sessions, and OpenCode's idle-event checkpoint hasn't been tried live. The one
[comparison](/docs/results) we have was run on 1.0 with the flow on; memory alone hasn't been
measured. [What it costs](/docs/concepts/cost) explains where the tokens go.
