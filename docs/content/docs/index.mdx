**Shared project context for developers and their coding agents.** Your AI tool writes the code.
Groundwork keeps what the project knows in your repo, as plain files: the spec, the decisions and
why they were made, the plan of small cards, the proof each card works, and a handoff saying where
things stand. A new session, a different tool or a teammate starts from those files, not from a
chat that's gone.

Checks back this up. Hooks refuse a commit that names a card without its evidence and your
approval, and `groundwork check` runs the same rules in CI.

<BuildLoopDiagram />

```bash
cd your-project
npx groundwork-ai init      # Claude Code, OpenCode, or plain markdown
```

Then open your AI tool in the project and type `/gw`.

## The three commands

| Type | When |
|---|---|
| `/gw` | Start, or carry on where you left off. It works out the next step. |
| `/gw-approve` | Accept the finished work; it's committed. |
| `/gw-reject` | Send it back, with a reason. |

Everything else (a quick fix, a stack decision, a handoff) you ask for in plain words; `/gw` reads
the helper it needs from `.groundwork/commands/`. [All commands →](/docs/reference/agent-commands)
