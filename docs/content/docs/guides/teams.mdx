**Commit `.groundwork/` and the whole team shares one memory.** A teammate who clones the repo, in
any tool, gets the same handoff, map, decisions and lessons, and is told what changed since.

## Three habits

- **Commit `.groundwork/`.** Local state is git-ignored for you. Committing the handoff doesn't make
  it out of date.
- **One writer per handoff.** The main checkout owns the main handoff. Everyone else, a teammate on
  a branch or a second agent, gets their own:

  ```bash
  npx groundwork-ai worker start auth-tests --goal "Write the auth test suite"
  ```

  See [Parallel agents](/docs/concepts/parallel-agents).
- **Write decisions and lessons down.** They are files, so a change shows up in the pull request
  like any other.

Before merging someone's branch, read their handoff and rerun their checks.

## Pull-request review as the approval

With the optional [flow](/docs/flow), each task branch carries its own handoff and pull-request
review is the approval. It is a working prototype: [Teams and pull requests](/docs/flow/pull-requests).
