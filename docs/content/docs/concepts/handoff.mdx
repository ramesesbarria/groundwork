---
title: "The handoff"
description: "Where the project stands right now, so the next session carries on instead of starting over."
---

**`.groundwork/HANDOFF.md` says where the project stands right now.** A session can end at any
moment (a closed laptop, a usage limit, a switch to another tool) and the next one continues.

## Save

```bash
npx groundwork-ai checkpoint --now "Login form renders; validation not wired" --next "Wire validation in src/login.ts"
```

The agent writes two sentences. `checkpoint` adds the facts from git: time, commit, branch and who
wrote it. It also adds an entry to the [journal](/docs/concepts/journal).

Other ways to save:

- Edit `HANDOFF.md`, then run `checkpoint` with no flags.
- Add `--blockers`, `--failing`, `--workers` or `--notes` to fill the other sections. Sections you
  don't name are kept.

## Resume

```bash
npx groundwork-ai brief      # what a session start shows
npx groundwork-ai status     # just Now, Next and the verdict
```

In supported tools the brief appears on its own at session start, with a
[freshness verdict](/docs/concepts/freshness). Where the handoff and the code disagree, the code is right.

## When it is saved

| When | Who |
|---|---|
| A step finishes, or the session is about to stop | The agent; `AGENTS.md` and `/gw` tell it to |
| A turn ends, before a compaction, at session end | Your tool's hooks, where the tool has those events |
| Any time | You |

A hook never invents a save. If nobody updated the handoff, it stays `behind` and the agent is asked,
once per commit, to write it. Hooks never block your work.

## What is in the file

```markdown
---
schema: 2
updated: 2026-11-15T08:41:12Z
head: 5c4bcc2…
branch: main
dirty: 0
tool: claude-code
body: 036856b545f8
deps: map=50622303e616 decisions=53200f643357 lessons=0f83fafeb146
---
# Handoff

## Now
Login form renders; validation is not wired to the API

## Next
Wire validation in src/login.ts, then add the first test

## Blockers
none

## Failing checks
none

## Workers in flight
none

## Notes
```

The top block is the stamp. Nobody types it; `checkpoint` writes it.

| Section | What goes there |
|---|---|
| Now (required) | What is in progress, and the last thing finished |
| Next (required) | The very next action, specific enough to start on |
| Blockers | What is stopping the work, or `none` |
| Failing checks | Failing tests, lint or build commands, or `none` |
| Workers in flight | [Parallel agents](/docs/concepts/parallel-agents) still going |
| Notes | Anything the next session would otherwise rediscover |

| Stamp key | What it records |
|---|---|
| `updated` | When it was saved |
| `head`, `branch` | The commit and branch it was written at |
| `dirty` | Uncommitted files, not counting `.groundwork/` |
| `tool`, `model`, `session` | Who wrote it, when known |
| `worker`, `state` | Worker handoffs only: the id, and `active` or `done` |
| `body`, `deps` | Fingerprints of the prose, and of the map, decisions and lessons |

Keep it short: the budget is 600 tokens. `checkpoint` refuses to stamp a handoff nobody has written.
With the [flow](/docs/flow) on, a `## Flow` section holds the phase, the current card and its status.
