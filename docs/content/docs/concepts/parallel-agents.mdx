---
title: "Parallel agents"
description: "Run several agents at once. Each keeps its own notes, so they never overwrite each other."
---

**One handoff, one writer.** Every extra agent gets its own handoff, so parallel work never
collides in git.

## Start a worker

From your main checkout:

```bash
npx groundwork-ai worker start auth-tests --goal "Write the auth test suite" --branch feat/auth-tests
```

The worker is now listed under **Workers in flight** in the main handoff and in
`.groundwork/work/LEDGER.md`. It saves to its own file:

```bash
npx groundwork-ai checkpoint --worker auth-tests --now "…" --next "…"
npx groundwork-ai brief --worker auth-tests
```

In a linked git worktree you can drop `--worker`. A worktree is always a worker, named after its branch.

## Finish a worker

```bash
npx groundwork-ai worker done auth-tests --outcome "accepted: 14 tests rerun, merged"
```

Before merging, read the worker's handoff and rerun its checks yourself. Its report is not a
verification.

## See who is working

```bash
npx groundwork-ai worker list
npx groundwork-ai status
```

The brief lists active workers too, each with its next step.

## Which handoff a session uses

1. `--worker <id>`, or the `GROUNDWORK_WORKER` environment variable.
2. `.groundwork/work/<branch>/HANDOFF.md`, if it exists for the current branch.
3. In a linked git worktree: the worker named after its branch.
4. Otherwise the main `.groundwork/HANDOFF.md`.

## Good to know

- Two sessions sharing one handoff get a warning, not a refusal. Give one of them a worker id.
- `worker start` and `worker done` run from the main checkout only.
- Working alone in a worktree? `--root` writes the main handoff.
- A worker's checkpoint doesn't touch the main handoff or the journal.
