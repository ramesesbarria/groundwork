description: "Where things are in the codebase, so a new session doesn't explore your repo from scratch."
---

**`.groundwork/MAP.md` says where things are:** the main folders, the entry points, the tests, and
the traps. A new session reads it instead of touring your repo again.

```markdown
# Map

## Layout
- `src/` the app (found)
- `src/login.ts` the login form and its validation (found)

## Entry points
- `src/login.ts` (found)

## Tests
- none yet

## Traps
- none found yet
```

## Who writes it

Your agent, on the first `/gw`. It marks each item *found* or *guessed*, and updates the map when
things move. There is no `map` command; you can edit the file yourself.

Keep it under about 40 lines. Link, don't explain.

## What `doctor` checks

- The map is filled in.
- The paths it names still exist.
- It is within its budget (800 tokens by default).
