**Memory is small on purpose.** It adds two things to a session, and both are capped.

| What | Cap | On a fresh install |
|---|---|---|
| Always loaded: `AGENTS.md` and your tool's skill list | `tokenBudget`, 2,000 | About 510 tokens in Claude Code, 440 in OpenCode |
| The brief, at session start | `budgets.brief`, 1,500 | About 145 tokens |

See your own numbers:

```bash
npx groundwork-ai doctor
```

These are estimates (characters ÷ 4). Decision records, lessons and the journal are read only when
a step needs them.

## Keep sessions cheap

A long chat re-sends its whole history on every call, so cost grows faster than the work does.
Memory lets you stop paying for that:

- **Start a new session** when a task finishes. The brief brings it up to speed.
- **Keep memory files short.** `doctor` flags one that is over; `compact` archives what it can.
- **Watch the thinking level.** High reasoning settings can dominate the bill.

## What the flow adds

The optional [flow](/docs/flow) runs each task through a tester, an implementer and a reviewer, so
it costs more. The one comparison we have, run on 1.0, is in [Results](/docs/results).
