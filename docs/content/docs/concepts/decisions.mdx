---
title: "Decisions"
description: "One record per decision, with the options and the reason, and a generated index: so 'what did we decide, and why?' always has an answer."
---

A new session can read the code. It can't read *why* the code is that way. **Decision records**
keep that: one file per choice, in `.groundwork/decisions/`, with the options that were weighed and
the reason for the pick. Agents are told not to reopen a decision in force without the human.

## Recording one

```bash
npx groundwork-ai decide "Use cookie sessions, not JWTs" --status accepted
```

This creates the next numbered record from the decision template and regenerates the index. `--status`
is `proposed` (the default), `accepted` or `superseded`. You or your agent then fill in the record:

```markdown
---
id: 0001
title: Use cookie sessions, not JWTs
status: accepted
date: 2026-11-15
---
## Context
What needs deciding and why now. Include the constraints that matter.

## Options
2 to 4 options. For each one: what it is, pros, cons, and what it would cost to switch away later.

## Decision
The option the human chose, in their words if possible.

## Consequences
What this makes easier, what it makes harder, and what to revisit later.
```

Record the choice the human made, or one that later work depends on. Never record the agent's own
preference as the human's decision: if the human took a recommendation, the record says
"accepted the recommendation" and quotes the reply.

## The index

`.groundwork/DECISIONS.md` is generated from the records. Don't edit it: change the record and run
`npx groundwork-ai index` (`--check` exits 1 when it is out of step; `checkpoint` and `decide` keep it
current, and [`doctor`](/docs/reference/cli#doctor) checks it).

```markdown
| ID | Decision | Status | Date | Record |
|---|---|---|---|---|
| 0001 | Use cookie sessions, not JWTs | accepted | 2026-11-15 | [0001-use-cookie-sessions-not-jwts.md](decisions/0001-use-cookie-sessions-not-jwts.md) |
```

## In the brief

The brief lists the decisions in force: every record that isn't superseded, with its status noted
when it isn't `accepted`. A session reads the full record before touching what it decided. The handoff's stamp
records a fingerprint of the decisions, so a session is told when one changed after it was written.

## Replacing a decision

Write a new record and set the old one's status to `superseded`, with a link. The old one isn't
deleted: [`compact`](/docs/concepts/budgets-and-compaction) moves superseded records to
`.groundwork/archive/decisions/`, where they stay searchable but leave the set every session loads.
The decisions budget is 600 tokens by default.

## With the flow on

With the [flow](/docs/flow) on, `gw-decide <topic>` runs the same record through a conversation, and
the planner runs it automatically before cards depend on a choice. **Groundwork never picks your
stack.** For every choice the build needs (framework, database, hosting, auth, a new dependency)
you get options with trade-offs, and the choice is recorded with the reason.

1. It checks whether an accepted decision already covers the topic.
2. It writes the record with status `proposed`: the context, and 2 to 4 options, each with pros, cons
   and what switching away later would cost.
3. It summarises the options in a few lines, then **waits** for your choice.
4. It records your answer **in your words**, sets it `accepted`, and fills in the consequences.
5. If the stack changed, the project's commands in `config.json` and `AGENTS.md` are updated.

### Recommendations are labeled, choices are yours

The agent may add one line starting **Recommendation:** naming the option it would pick and why.
It is always labeled, never mixed in with the options, and never a decision.

- With `experience: new`, a recommendation is included by default.
- With `experience: experienced`, only if you ask.
- At any experience level, if an option would **switch off part of the workflow** (no automated
  tests for the tester to write, no way to run the app), that's spelled out in the option's cons
  and a recommendation is included.

Saying *"you decide"* doesn't hand over the choice: the agent asks once, *"Shall I go with my
recommendation, B?"*, and only a clear yes counts, recorded as "accepted the recommendation".
Every option says how its tests run: "no automated tests" is never folded in quietly.

A new dependency or a stack change is also one of the few things the agent stops for on its own,
even in `per-phase` mode.
