---
title: "Freshness"
description: "Every session is told how far the handoff can be trusted, and exactly what changed since it was written."
---

**Old notes can't pass as current.** Every time a handoff is loaded, Groundwork compares it with
your repository and says what changed since.

```text
Handoff: BEHIND (written 0 min ago on main @ 5c4bcc2 by claude-code): 2 commits landed after it was written, changing 3 files.
  - 6a1a0f1 feat: logout endpoint
  - 2fce619 feat: session endpoint
  Changed files: src/api/logout.ts, src/api/session.ts, src/login.ts
  Files its Now/Next sections name have changed since: src/login.ts.
  Trust the code over the handoff where they disagree, then save an updated handoff.
```

The agent knows the handoff is two commits old and that a file it names has changed, so it checks
before acting.

## The verdicts

| Verdict | Meaning |
|---|---|
| `fresh` | Written at the current commit |
| `behind` | Commits landed since. Up to 8 are listed, with the files they changed |
| `diverged` | Its commit isn't in this branch's history: a rebase, a reset, another branch |
| `stale` | Older than `staleAfterDays` (14 by default) |
| `unstamped` | Never checkpointed, so there is nothing to compare |

When more than one applies, `diverged` wins, then `stale`, then `behind`.

A verdict can also note that the branch changed, that the map, decisions or lessons changed, or that
there are uncommitted files.

## Where you see it

| Where | What |
|---|---|
| Session start | The first lines of the brief |
| [`brief`](/docs/reference/cli#brief) | The full verdict; `--json` for scripts |
| [`status`](/docs/reference/cli#status) | One line |
| [`doctor`](/docs/reference/cli#doctor) | A suggestion when it is behind |

## Good to know

- Commits that only touch `.groundwork/` don't count, so committing the handoff keeps it fresh.
- Freshness checks the repository, not the prose. A handoff saved at the current commit is `fresh`
  even if what it says is wrong.
- Without git, only the age is checked.
