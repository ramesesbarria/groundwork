---
title: "Your first 10 minutes"
description: "From install to a session that resumes where the last one stopped. The example is a small web app with a login form."
---

This picks up after [installation](/docs/getting-started/installation): you have a git repo and have
run `npx groundwork-ai init`.

## 1. See what was installed

```bash
git status --short
```

A `.groundwork/` folder, an `AGENTS.md`, and your tool's files (`.claude/` and `CLAUDE.md` for Claude
Code, `.opencode/` for OpenCode). Open `.groundwork/HANDOFF.md`: it is empty on purpose. The agent
writes it; you don't have to.

## 2. Type `/gw` once

```text
You:   /gw
Agent: Nothing is recorded yet. What is this project called, and what does it do?
You:   A book club site. Members vote on next month's book.
Agent: Filled in AGENTS.md (found: npm test, npm run dev) and MAP.md (src/, entry point
       src/login.ts, no tests yet). What do you want to work on first?
```

On a new project `/gw` fills in what is empty: `AGENTS.md`'s project summary and commands, and
`.groundwork/MAP.md`, marking each item *found* or *guessed*. Then it asks what you want to work on.

## 3. Work, and save

Work as you normally do. When a step finishes, and before the session stops, the agent saves:

```bash
npx groundwork-ai checkpoint --now "Login form renders; validation not wired" --next "Wire validation in src/login.ts, then add the first test"
```

```text
Checkpoint saved: .groundwork/HANDOFF.md at 5c4bcc2 on main.
Journal: one entry added to .groundwork/JOURNAL.md.
```

The agent wrote the two sentences. The command wrote the rest: the time, the commit, the branch, how
many files were uncommitted, which tool wrote it, and a journal entry from git. In Claude Code and
OpenCode the hooks also checkpoint when a turn ends, before a compaction and when the session closes,
and ask the agent to save if the handoff is behind.

## 4. Come back later

Close the chat, come back tomorrow, or open a different tool or model. The session starts with the
brief. Suppose two commits landed in between:

```text
Handoff: BEHIND (written 0 min ago on main @ 5c4bcc2 by claude-code): 2 commits landed after it was written, changing 3 files.
  - 6a1a0f1 feat: logout endpoint
  - 2fce619 feat: session endpoint
  Changed files: src/api/logout.ts, src/api/session.ts, src/login.ts
  Files its Now/Next sections name have changed since: src/login.ts.
  Trust the code over the handoff where they disagree, then save an updated handoff.
```

The handoff doesn't pass itself off as current. The agent checks its Next step against the listed
commits, corrects it, saves, and carries on. That is [freshness](/docs/concepts/freshness).

## 5. Record what must outlast the session

```bash
npx groundwork-ai decide "Use cookie sessions, not JWTs" --status accepted
npx groundwork-ai lesson "Run migrations before the test suite" --origin "tests failed on a stale schema"
```

A [decision](/docs/concepts/decisions) keeps the options and the reason, so a later session doesn't
reopen it. A [lesson](/docs/concepts/lessons-ledger) keeps a mistake from repeating. Fill in each
record, and commit `.groundwork/` with your work.

## Where everything lives

| You want to know… | Look at |
|---|---|
| Where we stopped, and what's next | `/gw`, `npx groundwork-ai brief`, or `.groundwork/HANDOFF.md` |
| How much to trust it | The verdict at the top of `brief`, or `npx groundwork-ai status` |
| Where things are | `.groundwork/MAP.md` |
| What was decided, and why | `.groundwork/DECISIONS.md` and `.groundwork/decisions/` |
| Mistakes we learned from | `.groundwork/LESSONS.md` |
| What happened, commit by commit | `.groundwork/JOURNAL.md` |
| Whether memory is healthy | `npx groundwork-ai doctor` |

Working with several agents at once? See [Parallel agents](/docs/concepts/parallel-agents). Want a
spec, small cards with proof, and your approval before each commit? That is the optional
[flow](/docs/flow).
