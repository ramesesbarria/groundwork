---
title: "Configuration"
---

One file holds your settings: `.groundwork/config.json`. It's read fresh at each step, so changes
take effect immediately. Editors validate it against `config.schema.json` next to it.

```json
{
  "$schema": "./config.schema.json",
  "setup": "done",
  "approvalMode": "per-card",
  "autoCommit": true,
  "experience": "new",
  "tokenBudget": 2000,
  "guards": ["no-ai-trailers"],
  "enforce": { "commitGate": true, "protectHarness": true },
  "commitFormat": "[{id}] {title}",
  "commands": {
    "install": "npm install",
    "test": "npm test",
    "lint": "npm run lint",
    "build": "npm run build",
    "run": "npm run dev"
  }
}
```

## Fields

| Field | Type | Default | What it does |
|---|---|---|---|
| `version` | string | written by `init`/`upgrade` | The Groundwork version that last wrote your files; `doctor` compares it with the CLI |
| `setup` | `pending` \| `done` | `pending` | Whether `gw-setup` has run; `/gw` runs setup until it's `done` |
| `approvalMode` | `per-card` \| `per-phase` \| `at-end` | `per-card` | When you approve: every card, each phase, or once after the whole build. After setup, change it with `npx groundwork-ai mode` |
| `autoCommit` | boolean | `true` | Whether the agent commits each card when the mode allows; `false` and it tells you what to commit |
| `experience` | `new` \| `experienced` | `new` | How much the agent explains: one sentence per step and "How to check" every time, or terse summaries |
| `tokenBudget` | integer ≥ 500 | `2000` | Ceiling for what every session loads (`AGENTS.md`, `CLAUDE.md`, the command and subagent lists, session start), checked by `doctor` |
| `guards` | string[] | `["no-ai-trailers"]` | Guards to run before shell commands and file writes, by file name in `.groundwork/guards/`. The default blocks commits that credit an AI tool; remove it to allow them |
| `enforce` | object | both `true` | The built-in checks: `commitGate` and `protectHarness` — see below |
| `models` | object | — | Optional model per role, used only by adapters — see below |
| `commitFormat` | string | `[{id}] {title}` | First line of each card's commit; quick changes use `quick` as the ID |
| `commands` | object | empty | The shell commands agents run: `install`, `test`, `lint`, `build`, `run` |

## commands

The `commands` block is how the agent knows your project:

- **`test`, `lint`, `build`** are the checks a card must pass.
- **`run`** is how to start the app so a person *or* the agent can use it. Roles use it to check a
  card in the running app, and approval stops show it as "how to check it yourself."
- **`install`** is used when setting up.

Leave a command empty if the project doesn't have it. `gw-plan` fills these in when a stack is
chosen, and checks they actually run on your machine before writing them down.

## enforce

Two checks run before every shell command and file write, whatever `guards` lists:

- **`commitGate`**: a commit whose message names a card needs that card `done` and passing
  [`groundwork check`](/docs/reference/cli#check). In `per-card` mode on Claude Code, it also needs
  a message from you since the last commit.
- **`protectHarness`**: the agent can't remove a guard, set either of these to `false`, change
  `approvalMode` (except back to `per-card`), turn `autoCommit` back on after you turned it off, mark setup as not done, change existing guard or hook files, or
  take Groundwork's hooks out of settings.

Only you can turn them off, by editing this file yourself: the checks see the agent's tool calls,
not your editor. While `setup` isn't `done`, the agent may write the config freely.

## Models per role

Optional, and only used by adapters — the markdown core ignores it. A value is either one model
name for every tool, or an object keyed by adapter name, since each tool names models its own way:

```json
{
  "models": {
    "tester": "<a cheaper model>",
    "implementer": "<a mid-tier model>",
    "reviewer": {
      "claude-code": "<the strongest model>",
      "opencode": "<provider>/<model>"
    }
  }
}
```

The idea: cheaper models for the mechanical roles, the strongest for the reviewer's judgment. Leave
a role out to use the tool's default. `doctor` warns about role names that don't exist.

## Changing settings mid-project

Just edit the file — nothing else needs updating:

- Switching `approvalMode` changes the next stop, not past ones. Switch it yourself with
  `npx groundwork-ai mode`: the agent may go back to `per-card`, but nothing looser.
- Switching `experience` changes tone immediately (from the next step, since it's read each time).
- Raising `tokenBudget` after a deliberate decision is fine; `doctor` shows the real number.
