---
title: "Configuration"
---

One file holds your settings: `.groundwork/config.json`. It's read fresh at each step, so changes
take effect immediately. Editors validate it against `config.schema.json` next to it.

A project-memory install starts with this:

```json
{
  "$schema": "./config.schema.json",
  "version": "2.0.0",
  "flow": false,
  "tokenBudget": 2000,
  "budgets": {
    "brief": 1500,
    "handoff": 600,
    "map": 800,
    "decisions": 600,
    "lessons": 1200,
    "journal": 2500
  },
  "staleAfterDays": 14,
  "nudge": true
}
```

## Project memory

| Field | Type | Default | What it does |
|---|---|---|---|
| `version` | string | written by `init`/`upgrade` | The Groundwork version that last wrote your files; `doctor` compares it with the CLI |
| `flow` | boolean | `false` | Whether the optional [flow](/docs/flow) is on. Change it with `npx groundwork-ai flow on` or `flow off`, not by hand. A 1.x config with no `flow` key counts as on wherever the flow's files are |
| `tokenBudget` | integer ≥ 500 | `2000` | Ceiling for what every session always loads (`AGENTS.md`, `CLAUDE.md`, the skill and subagent lists), checked by `doctor` |
| `budgets` | object | see below | Estimated-token budgets for each memory file |
| `staleAfterDays` | integer | `14` | A handoff older than this is `stale`, whatever git says |
| `nudge` | boolean | `true` | Whether the stop hook asks the agent to save a handoff that is behind. `false` turns the reminder off |

### budgets

Estimated tokens (characters ÷ 4). See [Budgets and compaction](/docs/concepts/budgets-and-compaction).

| Key | Default | Over budget |
|---|---|---|
| `brief` | 1500 | The brief cuts itself to fit; `doctor` fails above 125% |
| `handoff` | 600 | `doctor` fails; `compact` archives sections a handoff doesn't define |
| `map` | 800 | `doctor` fails; shorten it by hand |
| `decisions` | 600 | `doctor` fails; `compact` archives superseded records |
| `lessons` | 1200 | `doctor` fails; merge or drop by hand |
| `journal` | 2500 | `doctor` fails; `compact` archives the oldest entries |

`npx groundwork-ai brief --budget <tokens>` overrides `budgets.brief` for one run.

### Environment variables

`GROUNDWORK_TOOL`, `GROUNDWORK_MODEL` and `GROUNDWORK_SESSION` say who is writing a checkpoint, and
`GROUNDWORK_WORKER` selects a worker's handoff. The matching flags take precedence.

## The flow's settings

With the [flow](/docs/flow) on, `config.json` has these too:

```json
{
  "setup": "done",
  "approvalMode": "per-card",
  "autoCommit": true,
  "experience": "new",
  "guards": ["no-ai-trailers"],
  "enforce": { "commitGate": true, "protectHarness": true },
  "commitFormat": "[{id}] {title}",
  "commands": {
    "install": "npm install",
    "test": "npm test",
    "lint": "npm run lint",
    "build": "npm run build",
    "run": "npm run dev"
  }
}
```

| Field | Type | Default | What it does |
|---|---|---|---|
| `setup` | `pending` \| `done` | `pending` | Whether `gw-setup` has run; `/gw` runs setup until it's `done` |
| `approvalMode` | `per-card` \| `per-phase` \| `at-end` | `per-card` | When you approve: every card or each phase (`at-end` is kept only for projects that already use it). After setup, change it with `npx groundwork-ai mode`. See [Approval modes](/docs/flow/approval-modes) |
| `integration` | `local` \| `pr` | `local` | `local`: `/gw-approve` gates card commits. `pr`: local commits are checkpoints and pull-request review is the approval; see [Teams and pull requests](/docs/flow/pull-requests). Only you switch it to `pr` once setup is done |
| `autoCommit` | boolean | `true` | Whether the agent commits each card when the mode allows; `false` and it tells you what to commit |
| `experience` | `new` \| `experienced` | `new` | How much the agent explains: one sentence per step and "How to check" every time, or terse summaries |
| `guards` | string[] | `["no-ai-trailers"]` | Guards to run before shell commands and file writes, by file name in `.groundwork/guards/`. The default blocks commits that credit an AI tool; remove it to allow them |
| `enforce` | object | both `true` | The built-in checks: `commitGate` and `protectHarness` |
| `models` | object | none | Optional model per role, used only by adapters |
| `commitFormat` | string | `[{id}] {title}` | First line of each card's commit; quick changes use `quick` as the ID |
| `commands` | object | empty | The shell commands agents run: `install`, `test`, `lint`, `build`, `run` |

### commands

- **`test`, `lint`, `build`** are the checks a card must pass.
- **`run`** is how to start the app so a person *or* the agent can use it; approval stops show it as
  "how to check it yourself".
- **`install`** is used when setting up.

Leave a command empty if the project doesn't have it. `gw-plan` fills these in when a stack is chosen,
and checks they actually run on your machine before writing them down.

### enforce

Two checks run before every shell command and file write, whatever `guards` lists:

- **`commitGate`**: a commit whose message names a card needs that card `done` and passing
  [`groundwork check`](/docs/reference/cli#check). In `per-card` mode, in a tool that records your
  messages, it also needs your `/gw-approve` for the work as it is now.
- **`protectHarness`**: the agent can't remove a guard, set either of these to `false`, set `flow` to
  `false`, change `approvalMode` (except back to `per-card`), switch `integration` to `pr`, turn
  `autoCommit` back on after you turned it off, mark setup as not done, change existing guard or hook
  files, change `.groundwork/lib/`, or take Groundwork's hooks out of settings.

Only you can turn them off, by editing this file yourself: the checks see the agent's tool calls, not
your editor. While `setup` isn't `done`, the agent may write the config freely.

### Models per role

Optional, and only used by adapters. A value is either one model name for every tool, or an object
keyed by adapter name, since each tool names models its own way:

```json
{
  "models": {
    "tester": "<a cheaper model>",
    "implementer": "<a mid-tier model>",
    "reviewer": {
      "claude-code": "<the strongest model>",
      "opencode": "<provider>/<model>",
      "codex": "<model>"
    }
  }
}
```

The idea: cheaper models for the mechanical roles, the strongest for the reviewer's judgment. `cursor` and `gemini` keys work the same way. Leave a
role out to use the tool's default. `doctor` warns about role names that don't exist.

## Changing settings mid-project

Just edit the file; nothing else needs updating. Switching `approvalMode` changes the next stop, not
past ones, and the agent may go back to `per-card` but nothing looser. Raising `tokenBudget` or a
budget after a deliberate decision is fine; `doctor` shows the real number.
