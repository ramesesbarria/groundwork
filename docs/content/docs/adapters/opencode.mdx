---
title: "OpenCode"
---

Groundwork's OpenCode adapter adds commands, subagents with permissions, and a plugin for guards
and session-start orientation. **It needs OpenCode 2.x** (tested with 2.0.16 and 2.0.18 — the
plugin format changed in 2.x, and 1.x-style plugins fail to load).

## What `init` adds

| Path | What it is |
|---|---|
| `.opencode/commands/gw-*.md` | One command per command file; each reads its core file and follows it |
| `.opencode/agents/gw-*.md` | A subagent for the tester, implementer and reviewer, with permissions |
| `.opencode/plugins/groundwork-guards.js` | Runs Groundwork's checks and your guards before each tool call, and tells each session where things stand |

OpenCode reads `AGENTS.md` itself, so no extra rules file is generated.

## Subagents with permissions

Planning runs in your main session, so the planner has a role file but no subagent.

| Subagent | Permission | Why |
|---|---|---|
| `gw-tester` | — | Writes and runs failing tests |
| `gw-implementer` | — | Makes them pass |
| `gw-reviewer` | `edit: deny` (covers edit, write and patch) | Judges and sends back; has a shell for checks only |

If you set [`models`](/docs/reference/configuration#models-per-role) with an `opencode` key, the model
is written into each subagent.

## Guards

The plugin hooks `execute.before` for every tool call, including `patch`/`apply_patch` edits. It
runs the same checks as in Claude Code: the **commit-gate** (a commit naming a card needs that card
`done` and passing [`groundwork check`](/docs/reference/cli#check)), **protect-harness** (the agent
can't remove guards, turn the checks off or switch to `per-phase`), then the guards listed in
`.groundwork/config.json`. A block throws, and OpenCode stops the call. If the config can't be read,
commits are blocked and everything else goes through, with a warning. New installs start with
`no-ai-trailers` on.

```json
{ "guards": ["no-ai-trailers"] }
```

Add a guard's name to the list and put its `.mjs` file in `.groundwork/guards/` — the same guard
files work in every adapter, because they're plain Node.

## Session start

The plugin also hooks the session's `context`: it adds the same few lines Claude Code's
session-start hook prints (from `.groundwork/hooks/session-start.mjs` reading `HANDOFF.md`) to the
system prompt, so a new session already knows which card is in progress and what's next. It's read
fresh each time, and skipped for Groundwork's own subagents, which get their card from the runner.

## Human-only commands

`/gw-approve` and `/gw-reject` are ordinary commands whose text says only the human runs them, and
the runner is instructed never to run them. The commit gate still refuses to commit a card that isn't
`done`, lacks evidence, or has no "approved by human" line in `per-card` mode.

What OpenCode doesn't have yet is Claude Code's check that *you* sent a message since the last
commit: Groundwork hasn't verified a plugin hook that fires only on the human's own messages. So in
OpenCode, "approved by human" is a line the agent is told to write only after you approve, and the
commit gate can't tell whether you actually did.
