title: "Claude Code"
---

Groundwork's Claude Code adapter turns the core into native skills, subagents and hooks. Everything
it generates points back into `.groundwork/`, so the core stays the single source of truth.

Needs **Claude Code 2.1.295 or later**, and Git for Windows on Windows (see Hooks below). Checked
with Claude Code 2.1.304 in 2026-10: a person built, rejected, reworked, approved and resumed a
project, including a stale approval, and scripted runs covered the commit gate and a guard that
can't run.

## What `init` adds

| Path | What it is |
|---|---|
| `.claude/skills/gw*/SKILL.md` | Skills for the three default commands (`/gw`, `/gw-approve`, `/gw-reject`); other helpers are read from `.groundwork/commands/` on demand |
| `.claude/agents/gw-*.md` | A subagent for the tester, implementer and reviewer, each with limited tools |
| `.claude/settings.json` | Three hooks: session-start orientation, the guard runner, and the approval recorder |
| `CLAUDE.md` | A short pointer whose first line loads `AGENTS.md`, then lists the commands and subagents |

## Skills that trigger themselves

Each command's description is written as a trigger — *"Use when the human describes a new app or
feature idea and there's no confirmed spec yet…"* — so Claude Code can pick the right one from a
plain request like *"I have an app idea"*. You don't have to learn command names.

`/gw-approve` and `/gw-reject` are **human-only**: they carry `disable-model-invocation`, so the
model can't run them as skills. That alone wouldn't stop a model reading the command file or
running `git commit` itself, so the commit gate backs it up: in `per-card` mode a card commit needs
your own `/gw-approve` for the work as it is now (see Hooks below).

## Subagents with different limits

The tester, implementer and reviewer each become a subagent with only the tools they need. Planning
runs in your main session, so the planner has a role file but no subagent.

| Subagent | Tools | Why |
|---|---|---|
| `gw-tester` | Read, Grep, Glob, Write, Edit, Bash | Writes and runs failing tests |
| `gw-implementer` | Read, Grep, Glob, Write, Edit, Bash | Makes them pass |
| `gw-reviewer` | Read, Grep, Glob, Bash — **no file-edit tool** | Judges and sends back |

The tester and implementer are *told* which files are theirs; nothing in the tools stops the
implementer editing a test, so the reviewer checks the diff for it. The reviewer has a shell for
running checks, and its role file allows it to write only into `.groundwork/evidence/`.

If you set [`models`](/docs/reference/configuration#models-per-role) per role, they're written into each
subagent — cheap models for mechanical roles, the strongest for review.

## Hooks

`init` **merges** into an existing `.claude/settings.json` instead of overwriting it, so your own
permissions and hooks survive.

- **SessionStart** (`startup|clear|compact`) runs `.groundwork/hooks/session-start.mjs`, which
  prints a few lines from `HANDOFF.md` — where things stand and the next step. It injects project
  state, not methodology, and prints nothing if `.groundwork/` isn't there.
- **PreToolUse** (`Bash|PowerShell|Write|Edit|MultiEdit|NotebookEdit`) runs
  `.groundwork/guards/run.mjs` before every shell command (Bash, or PowerShell on Windows) and file
  write. Exit code 2 blocks the action and shows the reason. It runs
  two built-in checks, then the guards listed in your config:
  - **commit-gate**: a commit whose message names a card needs that card `done` and passing
    [`groundwork check`](/docs/reference/cli#check), and in `per-card` mode your `/gw-approve` for
    the work as it is now. A commit that names no card needs a tag such as `[quick]`.
  - **protect-harness**: the agent can't remove guards, turn these checks off, relax the approval
    mode, switch to PR integration, run `migrate`, take Groundwork's hooks out of settings, or
    remove or move the folders that hold them. You can, in your editor or terminal.
- **UserPromptSubmit** runs `.groundwork/hooks/user-prompt.mjs` on each message *you* send (never on
  the agent's own actions) and records it in `.groundwork/.approvals/` (git-ignored). Only a
  `/gw-approve` message records an approval; any other message clears it.

What this enforces, and where it stops, is in
[Evidence and approval](/docs/concepts/evidence-and-approval#whats-enforced-and-where-it-stops).

**The guard fails closed.** If the tool call, `config.json` or a guard can't be read or run, the
runner blocks the call and says how to repair it. If the runner can't start at all (its file is
gone, or Node fails), the hook's `"onFailure": "block"` makes Claude Code block the call. That field
needs **Claude Code 2.1.295 or later**
([hooks reference](https://code.claude.com/docs/en/hooks)); earlier versions let the call through
when the guard can't run, and `doctor` reports the version it finds. On Windows, Claude Code runs
the hooks with Git Bash, so Groundwork needs Git for Windows. New installs start with
`no-ai-trailers` on.

When the guard is broken, every Bash, PowerShell, Write and Edit call is blocked until you repair it
from your own terminal:

1. `npx groundwork-ai doctor` says what's wrong.
2. If Groundwork's files are committed, restore them from Git, e.g.
   `git restore --source=HEAD -- .groundwork/guards .groundwork/hooks .groundwork/config.json .claude/settings.json`.
3. If they aren't, delete a damaged guard or hook file and run `npx groundwork-ai upgrade`, which
   writes it again. A missing `config.json` comes back with `npx groundwork-ai init`, which creates
   only missing files; set your choices in it again.
4. To take Groundwork out instead, `npx groundwork-ai uninstall --keep-state` removes the hooks and
   keeps your project files.

These checks stop the lazy or overconfident shortcut and make a deliberate one visible. An agent
set on getting around them can still use the shell in ways a hook can't foresee; for a hard gate,
run `npx groundwork-ai check` in CI.

## Checking the wiring

```bash
npx groundwork-ai doctor
```

Flags a missing hook, a guard hook without `"onFailure": "block"`, a Claude Code older than
2.1.295 (or says the version is unknown), a `CLAUDE.md` that doesn't load `AGENTS.md`, and generated
files that have drifted from what Groundwork would generate, with the command to fix each.
