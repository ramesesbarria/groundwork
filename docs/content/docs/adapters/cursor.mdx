---
title: "Cursor"
description: "Cursor conversations start with your project's brief and save as you go."
---

In Cursor, every new conversation starts with the brief, and your work is saved when a turn ends,
before a compaction and when the session closes. Type `/gw` to resume or save.

```bash
npx groundwork-ai init --adapter cursor     # or: npx groundwork-ai adapter add cursor
```

Open Cursor on the project folder itself. Hooks run from the project root, so a parent folder opened
as the workspace runs none of them.

## What happens when

| When | Hook | What happens |
|---|---|---|
| A conversation is created | `sessionStart` | The [brief](/docs/reference/cli#brief) goes into the conversation |
| A turn ends | `stop` | A [checkpoint](/docs/reference/cli#checkpoint). If the handoff is behind, a reminder to save is sent as the next message, once per commit |
| Before a compaction | `preCompact` | A checkpoint only. The summary is not told what to keep |
| The session ends | `sessionEnd` | A last checkpoint |
| You type `/gw` | Skill | Resume from memory, or save |

These hooks never block your work. Cursor documents `sessionStart` for new conversations only, so
for a resumed or compacted one, `AGENTS.md` tells the agent to run `npx groundwork-ai brief` first.

## Files it writes

| Path | What it is |
|---|---|
| `.cursor/hooks.json` | The hooks. Merged into your file, never replaced |
| `.cursor/hooks/groundwork.mjs` | A small script that hands Groundwork's text to Cursor in the form it expects |
| `.cursor/skills/gw/SKILL.md` | The `/gw` command |

Cursor reads `AGENTS.md` itself. It also loads `.claude/skills` and `.agents/skills`, so with
several adapters installed it may list `/gw` twice.

## With the optional flow on

`init --flow` or `flow on` adds:

| Added | What it does |
|---|---|
| `/gw-approve`, `/gw-reject` | Skills with `disable-model-invocation: true`: only you can invoke them |
| `.cursor/agents/gw-*.md` | Tester, implementer and reviewer subagents. The reviewer is `readonly: true` |
| `beforeShellExecution` guard | Runs the commit gate and your guards before every shell command. It fails closed (`failClosed: true`) |

What Cursor does not enforce:

| Gap | What it means |
|---|---|
| File writes aren't guarded | Only shell commands are checked. The commit gate still applies, because a commit is a shell command |
| Approvals aren't bound to your message | The commit gate can't tell that a human approved |

`init --flow` and `flow on` print this list.
