---
title: "Gemini CLI"
---

Groundwork's Gemini CLI adapter wires project memory into Gemini CLI: the brief at session start,
checkpoints, and `/gw` commands. **It follows Gemini CLI's documentation and has not been run inside
Gemini CLI.** Run `npx groundwork-ai doctor` after the first session.

Google's docs carry a notice that Gemini CLI was replaced by Antigravity CLI on 2026-06-18 for
unpaid-tier and Google One users; it stays available with paid API keys. Antigravity CLI is not
covered by this adapter.

```bash
npx groundwork-ai init --adapter gemini
```

Start Gemini CLI in the project root: hook commands are relative to it.

## What `init` adds

| Path | What it is |
|---|---|
| `.gemini/settings.json` | The hooks below. An existing file is merged, not replaced |
| `.gemini/hooks/groundwork.mjs` | A small script the hooks run. Gemini CLI shows plain stdout to the user only, so the script wraps Groundwork's text in `hookSpecificOutput.additionalContext` or `decision`/`reason` |
| `.gemini/commands/gw*.toml` | Custom commands `/gw`, and with the flow `/gw-approve` and `/gw-reject`; each reads the core command file and passes `{{args}}` |
| `GEMINI.md` | `@AGENTS.md` and one line about `/gw`. A `GEMINI.md` you already have gets the import added and keeps your text |
| `.gemini/agents/gw-*.md` | With the flow: a subagent for the tester, implementer and reviewer |

## What is automated

| Moment | Gemini CLI event | What happens |
|---|---|---|
| Session starts, resumes or clears | `SessionStart` | The brief is added as context (`additionalContext`). Gemini CLI documents no compaction source here |
| The agent finishes a response | `AfterAgent` | An automatic checkpoint; if the handoff is behind, `{"decision":"deny","reason"}` makes Gemini CLI retry with the reminder as the next prompt, once per commit |
| Before compression | `PreCompress` | An automatic checkpoint only: the hook can only show the user a message |
| Session ends | `SessionEnd` | A last automatic checkpoint (best effort: the CLI does not wait) |

No memory hook is fail-closed, and timeouts are 15 seconds or less (the setting is in milliseconds).

## What is instruction only

- After a compression nothing re-adds the brief; `AGENTS.md` tells the agent to run
  `npx groundwork-ai brief` and `GEMINI.md` loads `AGENTS.md`.
- The compression summary is not told what to keep.

## With the flow

`init --adapter gemini --flow` adds a `BeforeTool` hook for `run_shell_command`, `write_file` and
`replace`: the commit gate, the protection of Groundwork's own files and your guards. Exit code 2
blocks the call and its message reaches the model. **What Gemini CLI does not enforce:**

- **The guard is not fail-closed.** Gemini CLI treats a non-zero exit other than 2 as a warning and
  carries on, so a guard that cannot start lets the call through. Other tools (MCP) aren't checked.
- **Approvals are not bound to your message.** The recorder isn't wired, so the commit gate cannot tell
  that a human approved. `/gw-approve` and `/gw-reject` are commands you type; the documentation does not
  say whether the model can run one, so they are not marked human-only.
- **The reviewer is told, not stopped.** Its tool allow-list is `read_file`, `grep_search` and
  `run_shell_command` (it runs the checks), and the shell can write.
- **Project hooks are fingerprinted.** A changed hook is untrusted until you accept it.

`init --flow` and `flow on` print this list.

`models` in `.groundwork/config.json` with a `gemini` key sets each subagent's `model`.
