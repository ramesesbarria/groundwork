Project memory is plain markdown. Any agent that can read a file and run a shell command can use it,
with no adapter at all.

```bash
npx groundwork-ai init --adapter none
```

You get `AGENTS.md` and the `.groundwork/` folder, and nothing tool-specific. Most agents read
`AGENTS.md` on their own. If yours doesn't, point it there.

## What happens when

| When | What happens |
|---|---|
| A session starts | The agent runs `npx groundwork-ai brief`, because `AGENTS.md` says to |
| A step finishes, or the agent is about to stop | The agent runs `npx groundwork-ai checkpoint --now "…" --next "…"` |
| Before a compaction, or when the session ends | Nothing runs by itself |
| You want `/gw` | Ask: *"Read `.groundwork/commands/gw.md` and follow it."* |

Without hooks, saving depends on the agent remembering. You can always save by hand. Either way the
time, commit and branch come from git, so the next `brief` says how far behind the handoff is.

## Useful commands

```bash
npx groundwork-ai brief     # what a new session should read
npx groundwork-ai status    # where things stand
npx groundwork-ai doctor    # check the install and the memory
```

## With the optional flow on

Nothing is enforced:

- **No guards.** The rules are instructions. Nothing blocks a commit.
- **No bound approvals.** Nothing records that you approved.
- **No subagents.** The tester, implementer and reviewer run one after another in a single session.

For a hard gate, run `npx groundwork-ai check` in CI.
